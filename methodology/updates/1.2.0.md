## Adapted Decisions

- Comparative evaluation keeps original verdicts bound to frozen criteria, preserves failures and retries, separates development and held-out evidence, and limits label bias. Consequential evaluations validate measurement with controls and a bounded pilot before scale-up. Unknown resource use is not zero; missing interpretation is not permission to change thresholds.
- Change review evaluates semantic drift in aging work, confirms equivalent inputs before reusing evidence, and applies risk-proportionate depth without waiving required checks. A candidate cannot grant itself an exception to the policy governing its assessment.
- Design planning and critique preserve usability without animation and evaluate relevant starting, interrupted, resting, and repeating states. No animation library, capture procedure, fixed timing, export format, or universal motion quota is imported.
- Handoff and delegation distinguish individual evidence from combined-result evidence. Approval records retain source, scope, and conditions; a collaborator or unavailable owner cannot silently expand them.
- Scope control accounts for concurrent commitments and stops at authorized resource limits. It does not prescribe a metering service or turn estimates into measured use.
- Coordination distinguishes described capabilities from available, authorized ones. It neither installs missing capabilities nor requires a particular team.
- Method codification addresses missing judgment rather than masking implementation defects with more prose. Applicability appears early, duplicate rules are revised, and fresh-reader cases determine whether guidance is needed.
- Health assessment explicitly keeps fault injection and new instrumentation outside its read-only authority; final clean state alone cannot disprove transient effects.
- Supporting-source review adds completed-work and measurement-interval checks for performance claims; state/action coverage of durable effects; credible negative assertions after removal or renaming; and exact-wording checks only for actual consumed contracts or demonstrated behavior.
- Investigation challenges the premise shared by repeated failed remedies. Architecture considers separating ownership before coordinating shared state and reconciles unknown prior effects before retries. Planning specifies useful failure feedback without choosing error protocols or execution tools.
- Guidance reduction checks actual consumers and per-case outcomes and safety, not just total size or an aggregate score.
- Context restoration binds records to project/task/revision and verifies target state before replaying proposed writes. A procedure read is not evidence of prior effects.
- Scenario evaluation isolates each documented input rule so an earlier rejection cannot hide another missing guard. Error feedback and automated outcome signals must agree where applicable; setup failures do not establish target-path coverage.
- Design methods distinguish supported claims from illustrative data, expose missing proof and primary-action dependencies, and preserve local-only planning boundaries.
- Risk assessment checks in-scope variants of a validated cause without inheriting the original finding's reachability or severity. Change review considers indirect consumers and downstream handling of widened inputs.
- Planning compares genuinely different public-boundary shapes where consequential; process artifacts need an actual reader and decision, not fabricated implementation consumers. Investigation preserves interacting predecessor conditions and traces leaked state to its owner.
- Handoff compares completion against the authorized acceptance baseline, not criteria silently edited by the candidate. Retrospection revisits prior recommendations using evidence rather than administrative closure.

## Distribution Boundary

Only methodologies, shared methodological references, packaging metadata, and attribution ship in the plugin. The source snapshot explicitly adds all seven upstream entries, including excluded operational sources for future comparison, bringing it to 68 skill files. Its tool names and commands are intentional archival content and do not define installed behavior.

The update retains upstream notices and licenses alongside the raw snapshot. The plugin's license includes attribution and license text for the new motion and guidance-maintenance adaptations. Attribution is not a runtime dependency. No upstream setup or runtime code is executed.

The package guard rejects unexpected files and directories, executable files, symlinks, redirection of the skills location, and runtime metadata. Negative fixtures exercise scripts, hooks, external-service configuration, and unsafe metadata. This guard lives outside the distributable and does not become a skill dependency.

The previous 1.1.0 update was still uncommitted. Its full 218-path decision report is preserved in `1.1.0-review.json` before replacing the active lock, so advancing the baseline does not erase that review history.

Review depth follows applicability: current skill changes and relevant methodological contracts receive semantic review; host installation, runtime manuals, release history, and dated project-specific plans can be excluded by documented purpose and targeted scope inspection. Each such disposition records that basis, not a claim that every historical incident or runtime implementation was audited. Exact repeated content can share inspection evidence; filename similarity alone cannot establish equivalence.

## Behavioral Validation

A fresh-context, read-only evaluator applied the updated methods to seven synthetic cases. The evaluator received the cases and methods, not expected answers.

| Case | Observed outcome |
| --- | --- |
| Pilot favors an alternative after failure and retry; larger run exceeds approval | No established winner; retain all attempts, preserve holdout distinction, do not scale without authority |
| Aging change applies cleanly but contradicts current accepted contract | Block acceptance as-is; recommend rework or retirement without editing |
| Proposed animation hides content forever when disabled | Revise plan; require content availability and relevant transition evidence; no claim of rendered verification |
| Individually checked contributions combined without new checks; approval covers only one | Combined work not ready; separate component evidence from integration and preserve original approval scope |
| Retry fits per-attempt allowance but exceeds total limit; cleanup ownership uncertain | Stop; no retry or uncertain cleanup; retain ownership and resource gaps |
| Repeated failure comes from an implementation defect; proposed long universal guidance | Do not codify a prose workaround; identify separately authorized correction and avoid duplicate rules |
| Clean final state but alleged transient effect; reliability check needs fault injection | Partial assessment only; no injection or instrumentation under read-only authority |
