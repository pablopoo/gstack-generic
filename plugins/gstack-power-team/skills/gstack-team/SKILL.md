# Methodology Coordination

Modification notice: Rewritten and consolidated by Pablo Poo. Attribution and applicable terms: [NOTICE](../../NOTICE.md).

## Starting Point

Identify the requested outcome, existing decisions, current evidence, and authorized scope. Use [the method index](../../references/method-index.md) to select only methods that resolve a real gap. A method name identifies a way to work, not an executable operation.

## Method

- Reuse established decisions and evidence rather than restarting discovery.
- Read [the process map](../../references/process-map.md) when a result depends on several phases. Pass the actual output and remaining uncertainty to the next phase.
- In integrated planning, amend product and experience decisions before the final engineering review.
- Keep one lead responsible for synthesis. Delegate only distinct useful work; apply [the delegation contract](../../references/delegation-contract.md) and consult [collaboration responsibilities](../../references/collaboration-roles.md) when roles need clarification.
- Resolve routine choices within existing authorization. Ask for missing decisions only when they materially affect correctness, scope, or authority.
- Distinguish a described capability from one actually available and authorized. Missing capability is a limitation, not permission to install or configure it.
- Match verification to risk. Stop when the requested outcome has adequate evidence or an authorized resource limit is reached; report material limitations and the next bounded continuation when unfinished.

## Result And Scope

Return the requested artifact, decision, or completed local change with its relevant evidence. Plan-only and review-only requests end with those artifacts. These methods cover local development through readiness and handoff. They prescribe no execution environment, installation, model, or external action.
